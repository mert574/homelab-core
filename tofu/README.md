# Layer 2: guests (OpenTofu)

Declares the LXC containers and the k3s VM on Proxmox with the `bpg/proxmox`
provider. cloud-init / LXC init handles per-guest setup.

## What's here

- `versions.tf` - provider + version pins
- `providers.tf` - Proxmox connection (username/password + SSH to the node)
- `variables.tf` - inputs (connection, LAN, per-guest IPs)
- `pihole.tf` - Pi-hole LXC (`.101`)
- `postgres.tf` - Postgres LXC (`.102`, 512MB)
- `cloudflared.tf` - Cloudflare tunnel LXC (`.103`)
- `k3s.tf` - the k3s VM (`.104`) + Debian cloud image + cloud-init
- `admin.tf` - NixOS admin LXC (`.105`, on-demand)
- `ai.tf` - isolated NixOS AI sandbox (`10.10.10.10`, on-demand)
- `terraform.tfvars.example` - optional local overrides; bootstrap uses SOPS
  environment variables instead

The k3s VM installs k3s via cloud-init (`../cloud-init/k3s.yaml.tftpl`) with
flannel/kube-proxy/servicelb/traefik disabled so Cilium owns networking. Pi-hole
runs in a Debian LXC; the NixOS guests are configured through `../nix/`.

## Usage

The normal entry point is `bootstrap/bootstrap.sh` from the repository root;
see [the deployment runbook](../DEPLOY.md). It prepares templates and the
provider's SSH key, loads credentials from SOPS, and applies the configuration.

For later changes on the prepared Proxmox host, run from the repository root:

```sh
source scripts/load-env.sh
tofu -chdir=tofu init
tofu -chdir=tofu plan
tofu -chdir=tofu apply
```

The provider logs in as `root@pam` using `TF_VAR_pve_password`. SSH uses
`/root/.ssh/id_ed25519_pve`, generated by the bootstrap. There is no API-token
creation step.

If provisioning manually, prepare that SSH key and the guest templates first.
The bootstrap selects a Debian 13 LXC template and records its exact volume ID in
`debian_template.auto.tfvars`. It also builds the NixOS LXC template. An optional
`terraform.tfvars` can be based on the example, but `debian_ct_template` must also
be set when the bootstrap-generated file is absent.

## Notes

- `terraform.tfvars` and `*.tfstate` are gitignored. State is local for now;
  move it to a backend later if this grows.
- The k3s VM gets created here, but its k3s install flags (disable flannel,
  kube-proxy, servicelb, traefik so Cilium can take over) run via cloud-init.
  The Cilium install and everything above it is Layer 3 (`../cluster`).
